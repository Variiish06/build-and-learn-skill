Docker & Compose Sheet

From Lesson 0002Verified on the home server: Docker 29.8, Compose v5.5, postgres:18

Mental model

ImageRead-only template. One image → many containers.
ContainerRunning, isolated process. Its own writes die with it.
Port[IP:]HOST:CONTAINER forwarding rule. Default IP is all interfaces.
Named volumeStorage that outlives containers. Durability lives here.
Anonymous volumeAuto-created from an image's VOLUME. Orphaned when the container is re-created.

docker run

docker run -d --name scratch \
  -e POSTGRES_PASSWORD=pw \
  -v scratchdata:/var/lib/postgresql \
  -p 127.0.0.1:5432:5432 \
  postgres:18
docker ps                       # running containers
docker exec -it scratch psql -U postgres
docker logs -f scratch
docker inspect scratch --format '{{json .Mounts}}'
docker rm -f scratch            # keeps volumes
docker rm -f -v scratch         # also removes its anonymous volumes
docker volume ls
docker volume rm scratchdata

compose.yaml (engine db)

services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: engine
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}   # from .env (gitignored)
      POSTGRES_DB: engine
    ports:
      - "127.0.0.1:5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U engine -d engine"]
      interval: 5s
      timeout: 3s
      retries: 10
  # later:
  # api:
  #   depends_on:
  #     db: { condition: service_healthy }

volumes:
  pgdata:

docker compose

docker compose config           # validate and render
docker compose up -d
docker compose ps               # look for (healthy)
docker compose logs -f db
docker compose exec db psql -U engine -d engine
docker compose down             # keeps pgdata
docker compose down -v          # DELETES pgdata

Traps

  • Postgres 18+ mounts at /var/lib/postgresql. For ≤17 it's /var/lib/postgresql/data. Docker Hub: postgres
  • Docker bypasses ufw for published ports. Bind to 127.0.0.1. Docker docs
  • Running ≠ ready. Use a healthcheck plus condition: service_healthy. Docker docs
  • Inside Compose, other services reach Postgres at host db, port 5432. From the server itself, use 127.0.0.1:5432.

# Teaching Notes

## How the user learns best
- Brief concept first, with a real-world analogy, then show it in action.
- The user writes the important code themselves. Give hints, not full answers.
- Break things on purpose (race conditions, crashes) so the problem is seen before the fix.
- Short lessons tied directly to the next thing being built. No broad theory.
- End every topic with an interview-style quiz.
- Tie concepts to DDIA (Kleppmann), especially Ch. 7 Transactions (lost updates, isolation levels, locking).
- Track what they struggled with and revisit it (spaced retrieval). Log struggles below.

## Pacing
- 12-day hard deadline (ends 2026-10-30), 3-4 h/day. Each lesson should fit in roughly 45-90 min, including hands-on work.
- Lessons map to the day plan in MISSION.md. If behind schedule, cut breadth, never the failure-testing demo.
